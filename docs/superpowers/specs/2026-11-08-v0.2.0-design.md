# QuotaGlass v0.2.0 — Design

Date: 2026-11-08. Status: draft for owner approval. Base: `main` at `900cc82` (tag `v0.1.0`).
Product truth lives in `PRODUCT.md`. The v0.1.0 technical design stays in `docs/DESIGN.md`; this document changes only what it names.

## 1. Intent

The user's job is to switch accounts before a limit hits. v0.1.0 shows the numbers, but the window gets lost behind other apps, the layout does not answer "which account now?", and nothing warns before a limit runs out.

v0.2.0 makes QuotaGlass a small pill that is always findable, opens into a two-pane panel, warns at fixed levels, and points at the account with the most room left. It also replaces silent account discovery with explicit, user-started account connections.

## 2. Goals, non-goals, anti-goals

Goals:
1. The widget is never lost: a pill, always on top by default, draggable, position remembered.
2. One glance answers "which account now?": the "Best now" mark and the pill.
3. No surprise limit hits: native warnings at 50, 80 and 90%, plus a fast-burn mark.
4. Accounts are added by the user, with the vendor's own CLI doing every sign-in.
5. Glass stays the identity: Acrylic by default, Mica and Clear in Settings, light and dark themes.

Non-goals:
- Cursor, ChatGPT chat limits, API spend, any provider beyond Claude, Codex and Antigravity.
- Redeeming Codex banked resets inside the app.
- Time-to-limit forecasts.
- Auto-update, telemetry, crash upload.

Anti-goals (a build that does these has failed even if it works):
- QuotaGlass signs in, stores a vendor login, or renews a token itself.
- It writes to another app's files.
- It shows a number it cannot read from a real source, or prints a token or an email address.
- It looks like a gamer/neon HUD, a corporate dashboard, or a toy.

## 3. Constraints

- Platform: Windows 10 and 11 x64, Tauri 2, WebView2, plain TypeScript UI (no framework), Rust two-crate workspace (`crates/core`, `src-tauri`).
- Vendor terms (verified 2026-11-08): Anthropic forbids third-party apps from offering Claude.ai login or routing through subscription plans; Google forbids third-party use of Antigravity OAuth. Hence the read-only, CLI-driven account model in §6.7.
- QuotaGlass never refreshes OAuth tokens and opens other apps' files read-only.
- New dependency: `tauri-plugin-notification` (Tauri 2). Run `agentguard scan` on it before adding it.
- Windows build commands: `~/.cargo/bin/cargo.exe`, `npm.cmd`, and `tauri build` from a PowerShell script that adds `$HOME\.cargo\bin` to `$env:Path`.

## 4. Approaches considered (window model)

| | Approach | Trade-off |
|---|---|---|
| **A (chosen)** | One window that resizes once between pill size and panel size. | Reuses the existing window, saved position, off-screen clamp and Acrylic setup; one web view, no state sync. Cost: a short jump on each open/close, and the Acrylic resize-lag risk. |
| B (fallback) | A fixed pill window plus a separate panel window. | No resize, but two web views (more memory), event sync, and focus/`Esc`/always-on-top handled across two windows. |
| Dropped | One large transparent window with pill and panel drawn inside. | Acrylic blurs the whole window rectangle, and click-through regions on Windows are fragile. |

Owner chose A. Switch to B only if the Build test (§9, check 1) shows bad Acrylic resize lag on Windows 11 build 26200.

## 5. Visual direction (Impeccable, seed `284b48a6`, operate mode, code-led)

Owner chose **Pace Band**: each limit reads like a runner's pace wristband.

- THESIS: every limit is a pace strip; the question is "ahead of even pace or not, and which account still has room". It refuses the category default of plain progress bars on a dark dashboard.
- OWN-WORLD: smoked glass ground; strips with split ticks every 10%; a solid fill for "used"; a 2 px ink marker for even pace; tabular numerals everywhere; provider colours Claude `#d97757`, Codex `#10a37f`, Antigravity `#4c8df6`; one red for "ahead of pace" and errors.
- Raises carried from declined options:
  - One mark is reserved for "Best now" and used nowhere else: an inverted ink chip (light on dark, dark on light).
  - Stale or login-expired accounts render desaturated instead of gaining a badge.
  - Accent colour appears only on things that can be pressed or need action.
  - Numerals never change width on refresh.
- FIRST VIEWPORT (panel): providers list on the left (name, colour dot, account count); account detail on the right: account name and plan, then one pace strip per limit (5-hour, weekly, per-model) with % used and reset time.
- Themes: follow the Windows light/dark setting; Settings has System / Light / Dark.
- Motion: none when Windows "Animation effects" is off. Otherwise only short opacity/transform changes.
- Glass material: Settings choice of **Acrylic (default)**, Mica, Clear. Clear is OS Acrylic with a lighter tint and a 1 px light top edge; CSS `backdrop-filter` cannot blur the desktop behind a WebView2 window [Inference]. Mica is Windows 11 only; where a material is unavailable, use the CSS tint (`html.no-acrylic`).
- Accessibility (from `PRODUCT.md`): readable in about one second over any wallpaper; WCAG AA text contrast measured against the worst case behind the glass; full keyboard use; never colour alone (every state also has a number or a word).

Reference mockup: `.superpowers/brainstorm/411-1794117880/content/glass-material.html` (throwaway; not the build).

## 6. Behaviour

### 6.1 Window, pill and panel

- First launch: the pill docks above the taskbar at the bottom-right of the primary monitor's work area.
- The pill can be dragged anywhere. Its position is saved per drag end and restored at launch, with the existing off-screen clamp (`window.rs::clamp_to_monitors`).
- Always on top: on by default in v0.2.0 (v0.1.0 default was off). Settings keeps the switch.
- `skipTaskbar` stays true. Tray menu keeps Settings and Quit, and adds Show (brings the pill on screen).
- Pill content: up to 4 pinned accounts, each as colour dot, short name, mini strip, % used. With none pinned, it shows the single worst account (highest % used on its worst limit). "Best now" chip on whichever shown account has it; if the best account is not shown, the pill adds it as a fifth, compact item.
- Chevron on the pill opens the panel. The window resizes once: it grows upward from the pill; if there is not enough room above within the work area, it grows downward. The pill stays at the same screen position inside the panel.
- The panel stays open until the chevron is clicked again. Clicking another app does not close it. `Esc` closes it when the panel has focus.
- Panel layout: left pane providers (Claude, Codex, Antigravity, each hidden when it has no accounts and no "add" action); right pane the selected account (§6.3). "+ Add account" sits at the bottom of the left pane.

### 6.2 Limits and pace

- Each limit: `used %` (0–100), `window start`, `window end/reset`. Time passed % = elapsed / window length.
- Pace marker at time-passed %. Fill at used %.
- **Fast burn**: `used% >= 1.5 × passed%` **and** `used% >= 20`. Then the fill turns red and the row adds the words "fast burn". No time forecast.
- "Room left" of an account = `100 − max(used%)` over its limits that are currently readable.
- **Best now**: the readable, non-expired account with the most room left. Ties: the one whose worst limit resets soonest. No mark when fewer than two accounts are readable.

### 6.3 Account detail and cards

- Header: account display name (user-editable label; default from the source, never an email), plan name if the source gives it, freshness ("updated 1 min ago").
- One pace strip per limit with % used and reset time ("resets 3 h 30 min" under 24 h, otherwise weekday + time).
- Codex only: "Banked resets: N" when the usage response carries `rate_limit_reset_credits`; hidden when the field is absent. A **Redeem** button opens OpenAI's own usage page in the default browser. QuotaGlass never calls a redeem endpoint.
- Actions: Pin/Unpin (pill), Refresh, Remove (§6.7).
- States: loading, fresh, stale (desaturated + age), source error (reason in words), login expired (§6.7).

### 6.4 Warnings

- Native Windows notifications through `tauri-plugin-notification`.
- Levels 50, 80, 90% for every limit of every account.
- Each level fires once per limit window. A jump past several levels fires only the highest.
- A new reset time for that limit clears its fired levels.
- Fired levels persist on disk (`%APPDATA%\QuotaGlass\warnings.json`: account ID + limit ID + window reset time + highest fired level).
- 50 and 80: silent toasts. 90: plays the default sound and stays until dismissed (Windows "reminder"-style persistence).
- Text: "<Provider> · <account label>: <limit> at <N>% — resets <time>". No emails.

### 6.5 Providers and sources

- Providers: Claude, Codex, Antigravity. Users are assumed to have only the native tools (`claude`, `codex`, the Antigravity app / `agy`). Orca is optional everywhere and never required.
- Claude: `claude_direct` only (current login or added profiles).
- Codex: `codex_direct` only (current login or added profiles).
- Antigravity, in this order:
  1. **Antigravity app (primary, new `antigravity_app` source, `SourceKind::AntigravityApp`).** While the Antigravity IDE runs, it serves quota on a loopback port. Find the IDE's language-server process (`Antigravity.exe` / `language_server_windows_x64.exe`), list its listening loopback ports (Windows `GetExtendedTcpTable`), read the CSRF token from the server's own page (`GET /`), then `POST /exa.language_server_pb.LanguageServerService/RetrieveUserQuotaSummary` (header `x-codeium-csrf-token`). Response: groups (Gemini; Claude/GPT; plan pools) with 5-hour and weekly buckets, `remainingFraction`, `resetTime`. Used % = (1 − remainingFraction) × 100. Source for this method: open-source `ai-usagebar` 1.41.0 (`antigravity/fetch.rs`); field names and CSRF details are partly from a summary of that page and must be verified against the live IDE in Build.
  2. **`agy` CLI (later, if possible).** The `agy` server rejects quota calls without a CSRF token it does not publish. `ai-usagebar` reads agy's own `/quota` instead, but `agy -p "/quota"` printed nothing on the owner's PC (2026-11-08). Treat as unverified; add only if Build finds a working, documented-by-behaviour path.
  3. **Orca (optional).** `orca account list --json`, only after the user clicks "Connect Orca". Orca is never used for Claude or Codex.
  - **Never**: read the Antigravity Google session from Windows Credential Manager or call Google's Cloud Code quota API. Google's terms forbid third-party use of Antigravity OAuth (antigravity.google/terms).
  - With no source available, the Antigravity row says "Open Antigravity to see its limits".
  - [Unverified] whether Google's terms allow reading the IDE's local server. It uses no Google login, but it is not an official interface and can change.
- **Removed: `omp`** (code, settings key, README row, tests). **Removed: the v0.1.0 per-account source picker** (each account now has one source).
- Merge: one card per account ID (see §8 open item 1). No email matching. The "current login" card follows whichever account the CLI is signed into now.
- The word "unofficial" is removed from the UI.

### 6.6 Settings

Settings `version` 1 → 2. Migration keeps window position (as `pill_position`) and `refresh_minutes`; it drops every email-keyed v0.1.0 field (`overrides`, `sources`, `collapsed`, `hidden_services`) and `first_run_done`. Upgraded users see the first screen (§6.7) and reconnect in 2–3 clicks; the release notes say so. `always_on_top` becomes true (§8 item 2).

New or changed fields:

- `connected`: which one-click sources the user enabled: `claudeCurrent`, `codexCurrent`, `antigravityApp`, `orca`.

- `theme`: `system` | `light` | `dark` (default `system`).
- `material`: `acrylic` | `mica` | `clear` (default `acrylic`). Switching applies live: `clear_*` the current effect, then `apply_*` the new one (`window-vibrancy` 0.8.1). [Inference] no window recreation needed; prove in Build.
- `pinned_accounts`: ordered list of account IDs, max 4.
- `hidden_accounts`: list of current-login account IDs the user hid; Settings shows a "Hidden accounts" list with Unhide.
- `added_accounts`: list of `{ id, service, profile_dir }` (labels live in `labels`).
- `pill_position`: replaces `window` for the pill; panel size is fixed by the app.
- Remove `sources` (including `omp`) and `overrides`.

### 6.7 Accounts

No silent auto-detection. The user connects each account.

- **Claude and Codex — "Use my current login"**: one click. Reads `~/.claude` / `~/.codex` read-only, as v0.1.0 does.
- **"+ Add account"** (Claude or Codex): creates `%APPDATA%\QuotaGlass\profiles\<id>\`, then opens the real CLI in a new visible console with `CLAUDE_CONFIG_DIR` / `CODEX_HOME` set to that folder, running `claude auth login` / `codex login`. The vendor's sign-in runs in the user's browser. QuotaGlass then reads that folder read-only like the default login.
- **Login expired** (Claude added accounts; the login lasts about 8 h): the card shows "Login expired", desaturated, with **Open Claude**, which opens `claude` in a console with that profile's `CLAUDE_CONFIG_DIR`. Claude Code may or may not renew the login on start; GitHub issues report it often asks for `/login` (anthropics/claude-code #72017, #44945, #34306). The console stays open so the user can run `/login`. Codex logins last about 10 days; same pattern with **Open Codex**.
- **Remove**:
  - Added account: confirm dialog "Signs this account out on this PC and deletes its QuotaGlass profile". Then run `claude auth logout` / `codex logout` with that profile's env var, then delete the profile folder. `codex logout` is local only, with no vendor revoke (simplified.guide); whether `claude auth logout` revokes at the vendor is not confirmed, so the dialog promises only "on this PC".
  - Current-login card: Hide only (never logs out the user's CLI). It moves to Settings > Hidden accounts.
- **First screen (new install and upgrade)**: nothing is read until the user clicks. Buttons: "Use my current Claude login", "Use my current Codex login", "Use my Antigravity app", and a quieter "Connect Orca (optional)". Each click is recorded in settings (`connected`).
- **Antigravity**: "Use my Antigravity app" enables the `antigravity_app` source (§6.5). Accounts are whatever the running app is signed into; to add another, the user signs in inside Antigravity. QuotaGlass never touches Google sign-in or the `agy` login.
- Duplicates: one card per account ID across all sources and profiles.

### 6.8 Version

`0.2.0` in `package.json`, `Cargo.toml` (workspace + crates) and `src-tauri/tauri.conf.json`.

## 7. Security

- Load `security-gate` before Build and before Validate. Validate scanner: `ghost-security/scan-code` (general app diff), plus secrets and dependency gates and `cargo audit`.
- New process launches (`claude`, `codex` with env vars): absolute tool path from PATH, fixed argument lists, profile path generated by QuotaGlass (`<id>` is a random UUID), never text from the UI. Extends the pattern in `src-tauri/src/connect.rs`.
- Profile deletion: only paths under `%APPDATA%\QuotaGlass\profiles\`, canonicalised and checked before delete.
- Notification text and account labels: no tokens, no emails.
- CSP stays as in `tauri.conf.json`; the notification plugin needs its Tauri capability entry only.

## 8. Open items (decided by the builder unless marked owner)

1. **Account ID per source** (builder, verify): Claude `oauth/usage` / credentials, Codex `account_id` in the usage response, the Antigravity app's `GetUserStatus`, Orca's account list. If a source gives no stable ID, use a hash of the email internally, never shown.
2. **`always_on_top` migration** (builder): v0.1.0 has no "user changed it" flag; migrate to true for everyone and note it in the release notes.
3. **Panel size** (builder): fixed, about 440×300 at 100% scale, scaled with DPI.
4. **Banked resets field shape** (builder): verify `rate_limit_reset_credits` against a live response before showing it.
5. **OpenAI usage page URL for Redeem** (builder): use the page the Codex app links to; verify it before shipping.

3. Notification persistence for the 90% toast on Windows 10 and 11. If the plugin cannot keep it on screen, use a normal toast with sound; add no second dependency. (Builder-check call.)
4. `antigravity_app` against the live Antigravity IDE: process match, port, CSRF token, response field names, behaviour when the IDE is closed.
